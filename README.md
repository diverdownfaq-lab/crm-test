# DSRC CRM — тестовый проект

CRM департамента ДСРиР в одном файле `index.html` (без установки, без сервера). Данные хранятся в браузере, выгружаются вручную или автоматически в папку `data/`, а код (и позже данные) — в приватном репозитории GitHub.

## Что внутри

```
dsrc-crm/
├── index.html              CRM (открывать в Chrome или Edge)
├── sync.bat                двойной клик → отправить изменения в GitHub
├── sync.ps1                логика отправки: pull → проверка паролей → commit → push
├── init-repo.ps1           первичная привязка папки к GitHub (один раз)
├── setup-schedule.ps1      автоотправка по расписанию (Планировщик Windows)
├── .gitignore              что НЕ уходит в GitHub (data/backup)
├── setup/check.yml         проверка в GitHub Actions (init-repo.ps1 кладет её в .github/workflows)
├── docs/SERVER_API.md      контракт API для будущего сервера
└── data/                   создается кнопкой в CRM
    ├── latest/             текущие данные без паролей (имена файлов постоянные)
    │   ├── dsrc_crm.json   вся база (для восстановления/переноса)
    │   ├── dsrc_crm.xlsx   все таблицы на отдельных листах
    │   ├── clients.csv  deals.csv  contracts.csv  tasks.csv  events.csv
    │   └── meta.json       когда и кто выгрузил, сколько записей
    ├── history/            снимок JSON за каждый день
    └── backup/             ПОЛНАЯ копия с хэшами паролей — в GitHub не уходит никогда
```

## Форматы выгрузки — что для чего

| Формат | Где | Для чего |
|---|---|---|
| **JSON** | `data/latest/dsrc_crm.json` | Полная структура базы (клиенты, сделки, договоры, задачи, события, база знаний, настройки). Из него CRM восстанавливается через «Данные» → «Загрузить». Git хорошо показывает изменения построчно |
| **XLSX** | `data/latest/dsrc_crm.xlsx` | Все таблицы на листах «Клиенты», «Сделки», «Договоры», «Задачи», «Хронология». Для людей и для Power BI (Получить данные → Excel) |
| **CSV** (`;`, UTF-8 с BOM) | `data/latest/*.csv` | По файлу на таблицу. Открывается в Excel без настройки, удобно для Power BI «Из папки» и для сравнения версий в GitHub |
| **meta.json** | `data/latest/` | Дата выгрузки, кто выгрузил, версия CRM, количество строк — попадает в сообщение коммита |

Во всех таблицах есть колонки **ID**, **ID клиента**, **ID сделки** — по ним в Power BI строятся связи. Даты — в формате `ГГГГ-ММ-ДД`, суммы — числами.

Можно добавить и другие форматы, если понадобится: **Parquet** (большие объемы для Power BI/Python), **XML** (обмен с 1С/госсистемами), **PDF** (справки — уже есть в CRM через печать).

## Этап 1 (сейчас): в GitHub только код, данные — на диске

### Подготовка (один раз)
1. Установить **Git for Windows**: https://git-scm.com/download/win (все параметры по умолчанию). Вход в GitHub при первой отправке откроется в браузере (Git Credential Manager).
   Альтернатива без командной строки — **GitHub Desktop**: https://desktop.github.com
2. На github.com: **New repository** → имя `dsrc-crm` → **Private** → без README → Create. Скопировать адрес `https://github.com/<логин>/dsrc-crm.git`.
3. В папке `dsrc-crm`: правый клик по `init-repo.ps1` → «Выполнить с помощью PowerShell» (или в PowerShell):
   ```powershell
   powershell -ExecutionPolicy Bypass -File init-repo.ps1 -RepoUrl https://github.com/<логин>/dsrc-crm.git
   ```
4. Перенести свои данные из старого файла: в старом `DSRC_CRM new.html` → «Данные» → «Выгрузить JSON»; в `index.html` → «Данные» → «Загрузить».
   (В Chrome данные браузерных файлов общие, но выгрузка — надежная страховка.)

### Ежедневная работа
1. Работаете в `index.html`.
2. «Данные» → **«Сохранить в папку репозитория»** → первый раз выбрать папку `dsrc-crm` (браузер запомнит). Файлы появятся в `data/`.
   Галочка **«Автосохранение»** — после любого изменения через 30 секунд `data/latest` обновляется сам (пока вкладка открыта; после перезапуска браузера один раз нажмите кнопку).
3. Изменения кода → `sync.bat` (или автоматически по расписанию). На этапе 1 папка `data/` в GitHub не уходит — это задает `.gitignore`.

### Автоматизация
```powershell
powershell -ExecutionPolicy Bypass -File setup-schedule.ps1                  # каждые 30 мин
powershell -ExecutionPolicy Bypass -File setup-schedule.ps1 -EveryMinutes 60
powershell -ExecutionPolicy Bypass -File setup-schedule.ps1 -Remove          # выключить
```
Цепочка: **CRM (автосохранение) → data/ на диске → Планировщик → sync.ps1 → GitHub → Actions (проверка)**. Человеку остается только работать в CRM. Результат каждой отправки — в `sync.log`.

## Этап 2 (вариант 1): данные без паролей тоже в GitHub

Только после согласования (данные контрагентов конфиденциальны):
1. В `.gitignore` удалить строку `data/` и раскомментировать `# data/backup/`.
2. Запустить `sync.bat`. В GitHub появятся `data/latest` и `data/history`; история изменений по каждому клиенту видна во вкладке **History**.

Защита в три слоя: CRM вырезает пароли из `latest`/`history` → `sync.ps1` останавливает коммит, если видит `"pw":` или `data/backup` → GitHub Actions повторно проверяет после отправки.

## Важно про безопасность
- Репозиторий — **только Private**, доступ — поименно (Settings → Collaborators).
- В `index.html` зашиты демо-логины и стартовые пароли — смените их в CRM («Пользователи»), прежде чем давать доступ другим.
- Хэш паролей в браузерной версии простой (не криптографический), поэтому `data/backup` никогда не публикуется.
- GitHub — хранилище кода и версий, а не рабочая база для нескольких пользователей. Общая база — задача сервера (этап 3, см. `docs/SERVER_API.md`).

## Этап 3: сервер
Интерфейс к серверу уже готов: `index.html`, открытый по `http(s)://` с работающим API, автоматически переходит в общий режим (вход, совместное редактирование, вложения, ночные копии). Нужно написать серверную часть по контракту из `docs/SERVER_API.md` и положить её в этот же репозиторий в папку `server/`.

# Синхронизация данных и кода между компьютерами (этап 2, включен)

## Как устроено
```
Компьютер 1 (браузер)            GitHub (crm-test, private)            Компьютер 2 (браузер)
  база в браузере                                                        база в браузере
      │  кнопка «GitHub» / авто                                               ▲
      ▼                                                                       │ слияние по ID
  папка репозитория ──sync.ps1──►  data/nodes/pc-1.json  ──sync.ps1──►  папка репозитория
      ▲                            data/nodes/pc-2.json                       │
      └────────── слияние ◄──────  index.html (код)      ◄────────────────────┘
```
- У каждого компьютера свой файл `data/nodes/<компьютер>.json`, поэтому в Git нет конфликтов по данным.
- CRM читает файлы других компьютеров и сливает изменения по ID записей: новые записи добавляются, правки и удаления переносятся.
- `data/latest` (JSON, CSV, Excel) — общий срез для Power BI, `data/history` — снимок за день.
- `data/backup` (полная копия с паролями) в GitHub **не уходит**. Пароли у каждого компьютера свои.
- Новая версия `index.html`, пришедшая из GitHub, — CRM покажет плашку «Обновить».
- Пути к папке на компьютерах могут быть любыми: браузер запоминает выбранную папку, скрипты работают от своей папки.

## Компьютер 1 (уже настроен)
1. Открыть `index.html` в Chrome/Edge → кнопка **GitHub** вверху → выбрать папку репозитория → разрешить доступ («Разрешать при каждом посещении»).
2. Отправка: `sync.bat` или `setup-schedule.ps1` (каждые 30 минут).

## Новый компьютер
1. Установить Git for Windows (параметры — как на первом компьютере).
2. В Git Bash (папку выберите любую):
   ```bash
   git config --global user.name "имя"
   git config --global user.email "почта_GitHub"
   cd /c/              # или любая другая папка
   git clone https://github.com/diverdownfaq-lab/crm-test.git
   ```
   Если в сети не открывается GitHub, — та же настройка, что на первом компьютере:
   `git config --global http.curloptResolve "github.com:443:140.82.112.3,140.82.113.3,140.82.114.3"`
3. Открыть `crm-test\index.html` в Chrome/Edge, войти → кнопка **GitHub** → выбрать папку `crm-test` → **«Взять из репозитория»**.
4. Сменить пароль своей учетной записи (пароли на каждом компьютере свои).
5. Включить автоотправку: `powershell -ExecutionPolicy Bypass -File setup-schedule.ps1`.

## Если что-то пошло не так
- **«Конфликт в коде»** в `sync.log` — два человека одновременно поменяли `index.html`. Откройте папку в GitHub Desktop и выберите нужную версию. Данные не страдают.
- **Пользователь с другого компьютера не может войти** — Admin задает ему пароль на этом компьютере («Пользователи»).
- **Пропали данные в браузере** — «Данные» → «Загрузить» → `data/backup/dsrc_crm_full_ДАТА.json`, затем кнопка GitHub.
