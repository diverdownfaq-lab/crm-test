# Будущий сервер DSRC CRM — контракт API

В `index.html` уже встроен **серверный режим**. Если страница открыта по `http(s)://` и сервер отвечает на `/api/ping` значением `{"server": true}`, CRM перестает хранить данные в браузере (localStorage) и работает с общей базой на сервере: сохраняет изменения автоматически, раз в 4 секунды проверяет изменения коллег и сливает правки без потерь (трехстороннее слияние `merge3`).

Значит, сервер можно написать позже **без переделки интерфейса**: достаточно реализовать эндпоинты ниже (Node.js/Express, Python/FastAPI — на выбор) и раздавать `index.html` как статический файл.

## Эндпоинты, которые вызывает index.html

| Метод и путь | Тело запроса | Ответ при успехе | Назначение |
|---|---|---|---|
| `GET /api/ping` | — | `{server:true, empty:bool, ldap:bool, mail:bool}` | Есть ли сервер; `empty=true` — база пуста |
| `POST /api/bootstrap` | `{state}` | `200` | Первая загрузка базы (демо или ваша JSON-выгрузка) |
| `POST /api/login` | `{login, pw}` | `{uid}` + cookie сессии | Вход; пароль проверяет сервер (или LDAP) |
| `POST /api/logout` | `{}` | `200` | Выход |
| `GET /api/me` | — | `{uid}` / `401` | Кто вошел (по cookie) |
| `GET /api/state` | — | `{rev, state}` | Вся база + номер ревизии |
| `POST /api/state` | `{baseRev, state}` | `{rev}`; `409 {rev, state}` при конфликте | Сохранение. Если `baseRev` устарел — вернуть 409 и актуальную базу, клиент сам сольет правки и повторит |
| `GET /api/rev` | — | `{rev}` | Легкая проверка «изменилось ли что-то» (каждые 4 сек) |
| `POST /api/password` | `{uid, pw}` | `200` | Смена пароля (хранится на сервере, в state не попадает) |
| `POST /api/files?client=&name=` | файл (raw) | `{id, ...}` | Вложения к карточке клиента |
| `DELETE /api/files/{id}` | — | `200` | Удаление вложения |
| `GET /api/backups` | — | `{path, list:[{name,size}]}` | Список ночных копий |
| `POST /api/backup` | `{}` | `200` | Сделать копию сейчас |
| `GET /api/backups/{name}` | — | файл | Скачать копию |

Коды ошибок, которые понимает клиент: `401` — сессия истекла, `403` — нет прав (`{error}`), `409` — конфликт ревизий.

## Как GitHub участвует на этапе сервера

```
Разработчик ──push──► GitHub (код: index.html + server/)
                         │  GitHub Actions: проверки
                         ▼
                Сервер компании (git pull / деплой)
                         │
     Сотрудники ◄── http://crm.company.local ──► общая база (state.json / PostgreSQL)
                         │
                Ночная копия → папка backups/ (и, при необходимости, выгрузка
                data/latest без паролей в приватный репозиторий для Power BI)
```

- В GitHub хранится **код** (и при согласовании — обезличенные выгрузки).
- **Рабочая база живет на сервере компании**, а не в GitHub: GitHub не предназначен для конкурентной записи и не должен быть основным хранилищем персональных/коммерческих данных.
- Переход: в старой (браузерной) версии «Данные» → «Выгрузить JSON» → на сервере «Данные» → «Загрузить».
